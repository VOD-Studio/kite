# PRD: kite 配置 config.toml(Phase B)

> 状态:📋 待实现
> 关联:[roadmap Phase B](../kite-roadmap.md)、[CONTEXT.md「配置」术语与决策表](../../CONTEXT.md)
> 范围:`config.toml`(五项默认值)+ `config` 命令组(path / get / set)+ doctor 检查项。**配置目录与 session.json 迁移已完成**(`internal/cli/kit/paths.go` 的 `migrateLegacySession`),不在本 PRD 范围。
> 决策记录:2026-08-16 grilling 定稿,全部决议见 CONTEXT.md「不可逆/高代价决策」表。

## Problem Statement

1. **高频 flag 无法持久化默认值**:`--level` / `--out` / `--filename` 每次下载都要重复敲,追求 lossless 的用户每次都得传 `--level 3`。
2. **硬编码常量不可调**:下载并发、默认音质是代码里的字面量,没有用户侧出口。
3. **TUI(PRD-0016)将要消费配置**:TUI 客户端需要读默认音质等偏好,config 机制先落地,TUI 直接读,不返工。

## Solution

### 设计原则

**config key 只收「已存在的 flag 或硬编码默认值」**,不造新语义。每个 key 指向一个现成 flag,配置只是可持久的默认值。proxy / UI 偏好 / 多账号等不进(见 CONTEXT.md 暂缓项)。

### 配置项(五项,平铺)

| key | 类型 | 内置默认 | 对应承接点 |
|---|---|---|---|
| `level` | int 1-4 | `1` | `song url` / `song download` / `playlist download` 的 `--level` |
| `output` | `table` \| `json` | `table` | 全局输出模式(`--json` flag 与 TTY 检测之外的首选来源) |
| `download_dir` | string | `.` | `song download` / `playlist download` 的 `--out` |
| `filename_template` | string | `""`(即 `{artist} - {title}`) | `song download` 的 `--filename` |
| `workers` | int 1-5 | `3` | `playlist download` 的 `--workers`(并发数) |

> 实现期修正(2026-08-16):并发 flag 实际名为 `--workers` 且约定 1-5,config key
> 随之命名 `workers`(「key 指向现成 flag」原则),取代访谈时误写的 `concurrency` 1-16。

### 优先级链

```
--json flag > 非TTY自动JSON > config.toml > 内置默认
```

- 管道 JSON 契约**不被 config 覆盖**:`output = "table"` 不能让 `kite ... | jq` 拿到表格——config 是机器本地偏好,脚本契约是全局的。
- `output = "json"` 在 TTY 下生效(尊重人的偏好)。
- 其余四项为朴素 `flag > config > 内置默认`。

### config 命令组(进 help「工具」分组)

| 命令 | 行为 |
|---|---|
| `config path` | 裸打 `config.toml` 完整路径(脚本可用) |
| `config get <key>` | **裸打生效值**,不带格式(gh / jj / git 惯例,可在脚本中使用);config 未设时答内置默认 |
| `config get`(无参) | 表格列全部五项:key、生效值、**来源**(config / 默认) |
| `config set <key> <value>` | 校验通过后原子写盘,stdout 打一行确认 |

- 输出遵守 stdout/stderr 与 `--json` 全局约定,但**不走 proto 渲染层**(配置不是 rpc 域,Go struct 直接 marshal)。`config get <key>` 恒裸值(该 key 的值本身就是标量,「不带格式」优先);无参列表经 `kit.WantJSON()` 与 Render **同一条四层链**(`--json` > 非TTY自动JSON > config > 默认)——`config get | jq` 直接可用。
- 未知 key:get / set 均报错退非零(key 是固定枚举,拼错要早暴露)。

### 校验规则

| key | 规则 |
|---|---|
| `level` | 整数 1-4(与 flag 语义对齐:1=standard … 4=hires) |
| `output` | `table` \| `json` 二选一 |
| `workers` | 整数 1-5(与 `--workers` flag 契约一致) |
| `download_dir` | 只存不校验存在性(目录可后建,落地行为跟随现有 `--out` 逻辑) |
| `filename_template` | 占位符只允许 `{artist}` / `{title}` / `{album}` / `{id}`,未知占位符报错 |

**原则**:`set` 写盘前完成全部校验;**读取侧复用同一套校验函数**——手改文件绕过 `set` 入口同样被拦(类型/范围/枚举)。

### 文件机制

- 路径:`<ConfigDir>/config.toml`(`os.UserConfigDir()/kite/`,与 session.json 同目录)。
- 首次 `config set` 生成,顶部一行注释「本文件由 `kite config` 管理」;此后**整文件重写、不保留注释**。
- 原子写:tmp + rename(与召回池 history.jsonl 同惯例);文件 0600、目录 0700。
- **文件不存在 = 正常态**(全部用内置默认,不提示、不自动生成)。
- **文件存在但解析失败 / key 越界 = 硬错误**:命令拒绝执行,报错带 key 名与 `config path`,退出码 1。静默回退会掩盖用户设置(用户以为 level=3 实际下了 standard),比不可用更危险。
  - **豁免**:`doctor`(诊断工具,「配置」检查项要在坏文件下给出定位)与 `config path`(不读配置,是定位坏文件修复的入口)两命令放行,形成修复闭环。

### 周边集成

- `kite doctor` 加一项 config 检查(存在性 + 可解析),与版本/会话/补全同列。
- `config` 命令组进 help「工具」分组,`make docs` 刷新 `docs/cmd/`。
- **不进 onboarding 场景推送**(config 是用户带着问题来找的功能,主动推是噪音)。

### 实现落点

| 位置 | 内容 |
|---|---|
| `internal/cli/kit/config.go`(新) | Config struct + 加载/校验/读写;路径派生复用 `ConfigDir()`;提供 `userConfigDir` 同款可覆写 seam 供测试 |
| `internal/cli/config/`(新域包) | `config` 命令组(path / get / set) |
| `kit/output.go` `Render` | `output` 配置插入点:`k.JSON \|\| !stdoutIsTTY() \|\| config.output=="json"` → JSON |
| 各 flag 注册处 | `song url` / `song download` / `playlist download` 的 default 从 config 取(命令构造期读一次) |
| `internal/cli/doctor/` | 加 config 检查项 |

## 验收

```bash
kite config set level 3 && kite config get level        # → 3
kite song url --id 347230                                # 不传 --level,按 config 的 3 请求
kite config get download_dir && kite config get          # 前者裸值;后者表格带「来源」列
kite config set output json && kite search --keyword 周杰伦   # TTY 下也出 JSON
kite search --keyword 周杰伦 | jq '.[0]'                  # 管道仍必出 JSON(契约不破)
echo 'level = 9' >> "$(kite config path)" && kite search --keyword x   # 报错退 1,带 key 名
kite config set levil 3                                   # 未知 key 报错
kite doctor                                               # 显示 config 状态行
kite config set filename_template '{titel}'               # 未知占位符报错
```
