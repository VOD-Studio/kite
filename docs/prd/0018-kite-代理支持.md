# PRD: kite 代理支持(engine / CLI 双路径)

> 状态:📋 待实现
> 关联:[issue #22](https://github.com/VOD-Studio/kite/issues/22)、[PRD-0017 配置](0017-kite-配置.md)、[CONTEXT.md 决策表](../../CONTEXT.md)
> 前置:PRD-0017(config v1)——`proxy` 是 config 第六个 key,校验框架直接复用。本分支基于 `feat/cli-config` 栈式切出,config 合并后 rebase 回 main。
> 决策记录:2026-08-16 grilling 定稿(Q1 经 owner 确认,其余按「最优解不留坑」授权定稿)。

## Problem Statement

1. **海外用户访问网易云需要代理**。环境变量层今天已生效(engine 与 songdl 都走 `http.DefaultTransport` → `ProxyFromEnvironment`,`HTTPS_PROXY` 直接可用),但**无法持久化**:shell 环境变量是氛围层,会被企业代理污染,用户需要「这台机器上 kite 永远走我的代理」的确定性。
2. **下载路径与 API 路径可能分裂**。songdl 用 `http.DefaultClient` 直连 CDN,不经 engine transport——若只改 engine,`song download` 会出现接口走代理、音频直连的半代理状态。

## Solution

### 优先级链(决策见 CONTEXT.md)

```
--proxy flag > config proxy > 环境变量(HTTPS_PROXY/HTTP_PROXY,Go 默认) > 直连
```

- **显式设置 = 整体替换**:flag/config 设置代理时注入自定义 transport(`http.DefaultTransport.Clone()` + `Proxy: http.ProxyURL(u)`),`ProxyFromEnvironment` 完全不参与,无混合态。
- **都不设置 = 什么都不做**:默认 transport 保留环境变量行为(零代码白赚,server 侧同理)。
- **不做显式禁用哨兵**(`--proxy direct` 之类):逃生通道在同一层——`env -u HTTPS_PROXY kite ...`。

### 代理决策单一来源(防坑 1)

代理 URL 在 root 装配期**只解析一次**(flag > config,校验后),派生同一个 proxy transport 注入两处:

| 路径 | 注入点 |
|---|---|
| API 调用 | `engine.WithProxy(proxyURL)` → transport 的 `Proxy` |
| 音频下载 | songdl 的 HTTP client 共用同一 transport(经 kit 装配,downloadDeps 注入) |

不变式:**API 与下载看到的代理决策是同一个值**。任何新出现的直连 HTTP 路径(未来 TUI 的封面图加载等)必须从同一来源派生。

### 协议范围与校验(防坑 2 见「清除语义」)

- **scheme 白名单:`http` / `https` / `socks5`**——全部是 Go 标准库 `http.Transport` 原生支持,**零第三方依赖**。
- 校验规则(`--proxy` 与 config `proxy` 共用同一函数):
  - `url.Parse` 成功;
  - scheme ∈ 白名单(**必须显式写 scheme**,`--proxy 127.0.0.1:7890` 报错并提示加 `http://`——猜测默认值是坑);
  - host 非空;端口可选(缺省用 scheme 默认端口)。
- **清除语义**:`config set proxy ""` = 从 config.toml 移除该 key,回落环境变量。空值对 proxy 有真实语义(关闭),区别于 `download_dir`(空目录无意义故拒绝)。实现上:set 空值 → 从 set-keys 集合删除,不写 `proxy = ""` 行。
- 错误映射:坏 `--proxy` 值 → `ErrUsage` 退出码 2(参数拼写错误);config 里坏 `proxy` 值 → 既有硬错误链退出码 1。

### config 集成

- `proxy` 成为第六个 key:进 `configKeys` 枚举、无参列表(未设置时裸值输出空行,来源列「默认」)、补全枚举。
- `config get proxy` 回答 **config 层真相**(空 = 未配置);环境变量层与 flag 层它看不到——完整解析链由 doctor 呈现(三层来源的诚实处理,见下)。

### doctor「代理」信息行

- 显示解析链结果:`--proxy 覆盖: socks5://…` / `config: http://127.0.0.1:7890` / `环境变量: HTTPS_PROXY=…` / `直连`。
- **不做连通性探活**:「会话」检查已实际走一遍完整链路,代理问题会在那里暴露;独立探活受境内外网络差异影响易误报。
- 恒 pass(信息性行,无 FixHint)。

### server 侧

零改动。server 的 engine 同样默认 transport,`HTTPS_PROXY` 已生效——本 PRD 在 PR 描述与 server 文档中注记此行为即可。

## 非目标(明确排除)

- 不发明 `NETEASE_PROXY` 私有环境变量——与标准 `HTTPS_PROXY` 形成双真相。
- 不做按域名分流(`NO_PROXY` 在显式代理生效时对网易云请求不适用)——那是代理客户端(Clash 规则)的职责。
- 不做代理认证(username:password@host 之外的复杂形态由 URL 语法天然支持,不额外建模)。

## 实现落点

| 位置 | 内容 |
|---|---|
| `internal/netease/engine/transport.go` | `NewProxyTransport(u)`(engine 与下载路径共用的代理 transport 构造);`WithProxyURL(u *url.URL) Option`;`Engine.Apply`(root 在 flag 解析后装配期注入) |
| `internal/cli/kit/` | 代理解析与校验函数(flag/config 共用);proxy client 派生(songdl 注入) |
| `internal/cli/kit/config.go` | 第六 key `proxy`(校验 + 空值清除语义) |
| `internal/cli/root.go` | 全局 `--proxy` persistent flag;装配期一次解析(flag > config)注入 engine 与下载路径 |
| `internal/cli/doctor/` | 「代理」信息行 checker |
| `internal/cli/songdl/` | HTTP client 注入(不再固定 `http.DefaultClient`) |

## 验收

```bash
kite --proxy http://127.0.0.1:7890 search --keyword 周杰伦   # 经代理请求
kite --proxy socks5://127.0.0.1:7890 song url --id 347230    # socks5 可用
kite config set proxy http://127.0.0.1:7890                  # 持久化,压过环境变量
kite config get proxy && kite config get                      # 前者裸值;后者六项含来源列
kite config set proxy ""                                      # 清除 key,回落环境变量
kite --proxy 127.0.0.1:7890 search --keyword x                # 报错退 2,提示补 scheme
kite doctor                                                   # 「代理」行显示解析链
HTTPS_PROXY=http://127.0.0.1:7890 kite search --keyword x     # 环境变量层可用(现状保持)
kite song download --id 347230(--proxy 下)                    # 音频下载与接口同走代理
```
